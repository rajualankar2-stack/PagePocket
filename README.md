# PagePocket

A native iPhone/iPad app for opening **local HTML files** — from the Files app, iCloud Drive, or another app — and actually *interacting* with them.

Not a preview. Not a text dump. A real renderer with a real HTTP origin.

<p align="center">
  <em>Import a file, a folder, or a ZIP → it runs like a web app.</em>
</p>

---

## Why this exists

Every "open an HTML file" app on iOS hits the same wall: loading a file with `file://` gives the page an **opaque origin**. WebKit then blocks or breaks the things modern HTML actually needs:

| Feature | `file://` | PagePocket |
|---|---|---|
| Relative CSS / images / scripts | ✅ | ✅ |
| `fetch()` / `XMLHttpRequest` to a sibling file | ❌ blocked | ✅ |
| `<script type="module">` (ES modules) | ❌ blocked | ✅ |
| Web Workers | ❌ blocked | ✅ |
| `localStorage` / `IndexedDB` | ❌ unreliable | ✅ |
| Service Workers | ❌ | ✅ |

PagePocket fixes this by running a **read-only HTTP server bound to the loopback interface** inside the app, and serving each imported document from its own random path:

```
http://127.0.0.1:50123/r/<random-token>/index.html
```

The page now has a normal, stable origin. Everything above just works — including HTML apps generated by AI tools, exported dashboards, and self-contained game builds.

The listener is pinned to the loopback interface, so nothing is reachable from your Wi-Fi network or any other device.

## Features

**Import**
- Open a single `.html` file, an entire **folder**, or a `.zip` bundle
- Multiple selection in one pass
- Files-hand-off: "Open in PagePocket" from Files, Safari, Mail, or any share sheet
- Imported content also lives in the app's Documents folder, visible in the Files app

**Interact**
- Full JavaScript, CSS, canvas, WebGL and media playback
- Native `alert` / `confirm` / `prompt` dialogs (without these, pages that call them silently hang)
- `<input type="file">` support
- `window.open` and `target="_blank"` handled instead of ignored
- External links open in Safari, with a confirmation — local pages never get trapped

**Inspect**
- **Console** — captures `console.log/info/warn/error/debug`, uncaught exceptions and unhandled promise rejections, colour-coded and searchable
- **JavaScript runner** — evaluate expressions live against the page, with history
- **Page settings** — text-size zoom, document details, the served URL, and a button to clear cookies/local storage

**Read**
- Full-screen immersive mode
- Pull-to-navigate back/forward gestures
- Save a PNG screenshot of the rendered page
- Share the original file

## Getting it on your iPhone

This repo has **no Xcode project checked in as the source of truth** — it is generated from `project.yml` by [XcodeGen](https://github.com/yonaskolb/XcodeGen), so the project file never conflicts in git.

### Option A — Xcode (recommended, gives you a real device build)

```bash
brew install xcodegen
git clone https://github.com/rajualankar2-stack/PagePocket.git
cd PagePocket
xcodegen generate
open PagePocket.xcodeproj
```

Then in Xcode: select the **PagePocket** scheme → your iPhone → **Run**.

To install on a physical device you need to set your own signing team:
**Target → Signing & Capabilities → Team**. (Bundle ID `com.pagepocket.app` must be unique — change it if Xcode complains.)

### Option B — just build it in CI

`.github/workflows/build.yml` builds the app, boots a simulator, installs and launches it, and uploads a screenshot as an artifact. Push to `main` and check the **Actions** tab.

## Verifying it works

The app ships with two sample documents that are deliberately hard to fake:

**Welcome** — proves `fetch()` works against the same origin, plus a live capability checklist (canvas, WebGL, `localStorage`, ES modules, Web Audio).

**Capability Playground** — the real test:
- a genuine **ES module graph** (`js/main.js` → `js/geometry.js` + `js/render.js`)
- a **Web Worker** computing primes off the main thread
- a **canvas animation** driven by `requestAnimationFrame`
- a **localStorage** round-trip that counts your reloads

If all three lights are green, local HTML is running with full web-platform fidelity.

> Both of these fail in a plain `file://` viewer. That is the whole point.

│   │   ├── MimeTypes.swift         Correct content types — modules need JS MIME
│   │   ├── WebEngine.swift         WKWebView + console bridge + dialogs
│   │   └── DocumentSession.swift   Binds a Document to a served URL
│   ├── Views/
│   │   ├── LibraryView.swift       Home screen

│   │   ├── ConsoleView.swift       Devtools-style console
│   │   ├── ScriptRunnerView.swift  Live JS evaluation
│   │   ├── PageSettingsView.swift  Per-page controls

**Zero third-party dependencies.** Everything is Apple frameworks: `SwiftUI`, `WebKit`, `Network`, `Compression`, `UniformTypeIdentifiers`.

### Design notes

**Why a hand-written HTTP server instead of a WKURLSchemeHandler?**
A `WKURLSchemeHandler` gives you a custom scheme, not an HTTP origin — `fetch()`, modules and workers still behave differently, and `localhost` semantics are lost. A real loopback listener produces exactly the environment a web page expects, including correct MIME types, range requests for `<video>` seeking, and `index.html` directory resolution.

**Why copy files instead of referencing them in place?**
A security-scoped bookmark to a folder the user picked can be revoked, and the folder can move. Copying the whole tree into the app's Documents directory makes a document self-contained and durable, which is what "it just works tomorrow" requires.

**Why per-document random tokens?**
`/r/<uuid>/` means one document cannot address another document's files by guessing a path, even though they share one server.

## Privacy

PagePocket has **no network client**. It never fetches anything from the internet. The only server it talks to is itself, on `127.0.0.1`, bound to loopback so it is unreachable from other devices. There is no analytics, no tracking, and no account.

External links you tap are handed to Safari — PagePocket itself never loads them.

## Inspiration

Built after reviewing how existing projects approach local web content on iOS:

- [garynewby/WKWebView-Local](https://github.com/garynewby/WKWebView-Local) — loading local files and Swift↔JS messaging
- [vasilevkin/WKWebViewLocalAssets](https://github.com/vasilevkin/WKWebViewLocalAssets) — local HTML with CSS and images
- [tech4242/wkwebview-local-resources](https://github.com/tech4242/wkwebview-local-resources) — local resource loading patterns
- [humblerhy-maker/HTML-Viewer](https://github.com/humblerhy-maker/HTML-Viewer) — treating uploaded HTML files as self-contained apps
- [xFyerr/HTML_Viewer_Apple](https://github.com/xFyerr/HTML_Viewer_Apple) — full-screen local HTML viewing from the Files app

The common finding across all of them: `loadFileURL` gets you rendering, but not a *working web app*. PagePocket takes the extra step of serving over loopback HTTP to close that gap.
